我赞成直接新建 **`opencode-agentic-workflow`**，而不是继续在 `opencode-dynamicworkflows` 上硬改。

你的旧项目现在已经不是“小插件”了，它实际上已经有 Workflow Runtime、DSL、并行执行、组合控制流、verify、checkpoint、resume、scheduler、nested workflow、TUI observability 等完整体系；README 对它的定位也是“Main Agent 生成 JS orchestration script → Runtime 调度独立 sub-session → 主上下文只拿聚合结果”。 当前 npm 包还明确依赖 `@opencode-ai/plugin 1.18.27`，属于典型的 v1 实现。

而 OpenCode v2 官方已经明确：**v1 plugin implementation 不能直接运行在 v2**；插件入口从旧 API 迁移到 `Plugin.define({ id, setup(ctx) })`，包也变成新的 `@opencode/plugin`，server/client API 同样换了 contract。[OpenCode](https://opencode.ai/v2/docs/migrate-v1?utm_source=chatgpt.com)

所以我建议形成非常清晰的两代产品：

| 项目 | 定位 |
|---|---|
| `opencode-dynamicworkflows` | OpenCode v1，进入维护模式 |
| **`opencode-agentic-workflow`** | **OpenCode v2 原生 Agentic Workflow Engine** |

### 新项目不要“复制然后修到能跑”

更好的做法是：

```text
opencode-dynamicworkflows
        │
        │ 提取成熟设计
        ▼
┌──────────────────────────┐
│ Workflow Core            │
│                          │
│ agent()                  │
│ parallel()               │

└─────────────┬────────────┘
              │
              ▼
┌──────────────────────────┐
│ OpenCode V2 Adapter      │
│                          │
│ Plugin.define()          │
│ ctx.tool                 │

│ ctx.event                │
│ ctx.storage              │

└─────────────┬────────────┘
              │
      ┌───────┴────────┐
      ▼                ▼
   Runtime            UI
   Engine          Observability
```

也就是说：

**迁移 Workflow 的“思想和核心逻辑”，不要迁移 v1 的 OpenCode integration layer。**

这是这次重构最重要的一条原则。

# 哪些东西应该重写

这部分不要兼容旧代码，直接 V2-native。

### 1. Plugin Entry

V1 大概是：

```ts
export const Plugin = async (...) => {
    return {
        tool: {},
        event: ...
    }
}
```

V2 官方推荐：

```ts
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
    id: "agentic-workflow",

    async setup(ctx) {

    }
})
```

V2 的核心变化就是把能力围绕 `ctx` 注册。[OpenCode](https://opencode.ai/v2/docs/build/plugins/?utm_source=chatgpt.com)

---

### 2. Agent Executor

旧：

```text
Workflow Runtime
        ↓
OpenCode v1 client
        ↓
session
```

新：

```text
Workflow Runtime

        ↓

AgentExecutor interface

        ↓

OpenCodeV2Executor

        ↓

ctx.session
```

强烈建议增加这个抽象：

```ts
interface AgentExecutor {

    execute(
        task: AgentTask
    ): Promise<AgentResult>

}
```

这样：

```text
agent()
```

根本不知道 OpenCode 的存在。

以后甚至可以出现：

```text
OpenCodeExecutor
ClaudeCodeExecutor
CodexExecutor
PiAgentExecutor
```

这个改变会让你的项目从：

> OpenCode 插件

逐渐变成：

> Agentic Workflow Engine + OpenCode Runtime Adapter

这个战略价值比单纯适配 V2 大很多。
