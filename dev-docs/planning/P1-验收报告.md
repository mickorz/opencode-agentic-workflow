# P1 验收报告

日期：2026-10-03 ｜ 版本 v0.2.0 ｜ 状态：**通过**

## P1 目标（达成）

> 让 Agentic Workflow 具备「执行 → 确定性检查 → 语义验证 → 失败处理 → 人工审批」的可靠执行链。

## 端到端验收（真实运行，非 mock）

验收命令（带看门狗与模型预检，见经验沉淀）：

```text
opencode run --model glm/glm-5.3-flash
  "使用 workflow 工具，参数 flow=reliable，topic=为什么天空是蓝色…"
```

真实链路结果：

| 环节 | 实现 | 结果 |
|---|---|---|
| 1. 执行 | agent 子会话（glm-5.3-flash） | 产出 579 字符分析 |
| 2. 确定性检查 | `assert(() => commandSuccess("node --version"))` 真实命令 | 通过 |
| 3. 语义验证 | 2 个 reviewer 子会话并行评审 + 宽松 JSON 解析 | 2/2 通过 |
| 4. 人工审批 | PolicyCheckpointGate（auto-approve） | 已批准 |
| 5. 返回 | 报告文本经 workflow tool 返回主会话 | 原样输出，exit=0 |

失败路径同样经单测验证：check 失败 fail-fast 中断（reviewer 不执行）、verify 失败中断（checkpoint 不执行）、checkpoint 拒绝中断——逐环节防泄漏。

## 过程中抓到并修复的问题

- reliable 链初版误用非抛错版 `check()`/`verify()`，失败不中断——单测当场暴露，改用 `assert()`/`assertVerify()` 严格版（评审必严格，观测用宽松）
- reviewer prompt 未禁工具，补上「不要调用任何工具」（递归死锁教训的泛化）

## 明确不做（P1 范围外）

- resume / journal（与 checkpoint 是两个问题，待 checkpoint 语义稳定后另期处理）
- 交互式审批（TUI 双形态 `@opencode/plugin/tui` 的 `ui.dialog.confirm` + RPC）→ **P2 候选**
