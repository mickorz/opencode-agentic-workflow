# 手动验收清单：TUI 面板 + 安装器交互路径

**基线版本**：v0.5.0 ｜ **性质**：人工验收（TTY 交互与视觉呈现无法自动化，边界声明见 README「TUI 进度面板」章节末尾）

> **前置**：v0.5.0 尚未上架 npm（CI OIDC 卡 TP 表单，见 `planning/TODO.md`
> blocker 项）。**等发布通了再做本清单**——否则 `npx` 装到 0.4.0（无 bin，
> 报 `could not determine executable to run`；P2-13 session 区也不存在）。
>
> **发布前测试路线（link，推荐）**——注意插件与 CLI 解析规则不同：
>
> ```bash
> # CLI 侧：link 后 bin 直连仓库 dist，rebuild（npm run build）即生效
> cd /path/to/opencode-agentic-workflow && npm link
> cd /path/to/agw-manual-test && npm link @mickorz/opencode-agentic-workflow
> npx opencode-agentic-workflow install        # 注意用 bin 名，不是包名
> ```
>
> - **包名形式的插件条目（project/global 模式写入）不走项目 node_modules**：
>   opencode 经自身缓存 `~/.cache/opencode/npm/` 拉 registry（当前 0.4.0），
>   link/tarball 都不参与（实测坑见
>   `experience/opencode插件npm包名解析走自身缓存.md`）→ 面板测的是旧版
> - **面板用例（P 系列）前**：把 `opencode.json` 插件条目的 `package`
>   从包名改成仓库 dist 绝对路径（`…/opencode-agentic-workflow/dist/plugin`，
>   dev-examples 规范做法）；改 dist 后需**重启 opencode service**
> - **I-6（locked 模式）勿在 link 状态下测**：locked 流程会
>   `npm install @mickorz/…`（registry 0.4.0），把 link 顶掉；测 I-6 用
>   tarball 路线或发布后走
> - tarball 路线（`npm pack` → 测试目录 `npm i ./…tgz`）同样只覆盖 CLI 侧，
>   效果与 link 同；区别是 tarball 不会被 npm install 顶掉、但不随 rebuild 更新

自动化已覆盖（**不需要**在这里重复测）：server 侧事件发射、board 维护、
RPC 契约（snapshot/detail/session）、journal 落盘（含 sessionIDs）、
安装器无头路径（flags 全量 + install→uninstall 全链）、config 层纯函数。
本文只测「必须真人坐在终端前」的两块：**面板渲染**与**安装器交互（TTY）**。

## 0. 环境准备

```bash
# 干净的测试目录（勿在本仓库内测——父链 node_modules 污染）
mkdir agw-manual-test && cd agw-manual-test && git init -b main
# 交互式安装（本身就是安装器用例 I-1）
# · 发布后：npx @mickorz/opencode-agentic-workflow install
# · 发布前：按上方前置块的 tarball 路线装好后 → npx opencode-agentic-workflow install
#   安装方式选「当前项目」；模型按提示填 providerID/modelId（如 glm/glm-5.3-flash）
#   journal / skills 均确认启用（缺省值即推荐值）
```

面板测试需要一个 flow。在项目根建 `flows/hello.json`：

> 为什么手写？测运行时要**确定性夹具**（步骤/条目数钉死，断言稳定），且
> pipeline 步是专为 P-5 多会话回放设计的。日常其实不必手写：内置
> `flow=smoke` 开箱即跑；或对话里让 agent 用 workflow-authoring skill
> 经 `workflow_define` 直接生成（零文件编辑）。详见
> `dev-docs/design/从v1提示词生成到v2注册式流程-设计动机解析.md`。

```json
{
  "id": "hello-manual",
  "version": "1.0.0",
  "steps": [
    { "name": "ask", "agent": "用一个词回答：1+1 等于几。禁止调用 workflow / workflow_metrics 工具。" },
    { "name": "fanout", "pipeline": "针对「{{item}}」写一句不超过10字的话。禁止调用 workflow / workflow_metrics 工具。", "items": ["甲", "乙"] }
  ],
  "output": "ok"
}
```

把 `"workflows": ["flows"]` 加进 `opencode.json` 里插件条目的 `options`
（相对路径以项目目录解析）。然后 `git add -A && git commit -m init`。

## 1. TUI 进度面板（P2-8 / P2-8b / P2-13）

> 每条勾一个：☐ 通过 ☐ 不通过（备注现象）。**P-6 需 v0.5.0+**（session 区是新面）。

**P-1 打开与空态**：`opencode`（TUI）→ 输入 `/workflow`（或命令面板搜 "Workflow progress"）
- 面板出现，标题 `Agentic Workflow`
- 无 run 时显示 `(no runs yet — start one with workflow_start)`
- 不报错、不闪退；`q`/正常导航退出面板后再开正常

**P-2 实时进度**：主会话发起 run（可直接粘贴）：

> 调用 workflow 工具：flow=hello-manual，完成后一句话报告结果。

- run 行出现，随事件实时刷新（无需手动重开面板）
- 步骤图标正确轮换：`·`（pending）→ `▶`（running）→ `✓`（completed）
- 步骤名与 flow 一致：`ask` → `fanout`
- run 完成后步骤行不再变化

**P-3 失败呈现**：把 `hello.json` 里 `ask` 的 prompt 改成让模型调用被禁工具的写法（或临时改错 agent 名）再跑一次
- 步骤行显示 `✗`，下一行 `↳ <失败摘要>`
- run 行标 `✗`；后续步骤不执行

**P-4 节点详情区（detail）**：任一 run 结束后
- `── detail` 分隔行出现
- 含 runId、args 预览、每步输出/错误预览（长文折行 + 截断，不刷屏）
- agent 步带 token/模型后缀（形如 `· 1.5k tok · glm/glm-5.3-flash`）
- 同一状态不重复拉取（面板反复开关内容一致）

**P-5 会话回放区（session，P2-13）**：任一 run 结束后
- `── session` 分隔行出现在 detail 区之后
- 头行 = 步骤名 + 会话 ID（`ses_…`），回放的是**最后一个带会话的步骤**（hello-manual 应为 `fanout`）
- 消息前缀正确：`❯` 用户提问 / `·` 助手回答
- pipeline 步多会话时面板自动取最后一个；不报错、无空行区残留

**P-6 历史种子**：完全退出 TUI 再进，`/workflow`
- journalDir 里的历史 run 仍在（newest first），含步骤树与 detail

**P-7 checkpoint 弹窗**（可选；需 flow 含 checkpoint 步或未传 `checkpointMode=auto-approve`）
- run 到 checkpoint 时 TUI 弹确认框：「批准继续 / 拒绝中止」
- 批准 → run 继续；拒绝 → run 失败收口，journal 记录原因
- 弹窗期间面板正常刷新，不互相遮挡错乱

**P-8 降级路径**：`opencode.json` 里临时删掉 `journalDir` 配置，重启 opencode，`/workflow`
- 面板与实时进度正常
- detail / session 区**静默不出现**（不报错、不渲染空段）

## 2. 安装器交互路径（P2-10）

> 无头路径已被单测/打包验收覆盖，这里只测 TTY 交互。每条：☐ 通过 ☐ 不通过（备注）。

**I-1 交互安装（project 模式）**：`npx @mickorz/opencode-agentic-workflow install`
- 提问顺序：安装方式（select 三项：全局/当前项目-推荐/锁定版本）→ 模型（text，带占位示例）→ journal（confirm，缺省 Y）→ skills（confirm，缺省 Y）→ 开始安装（confirm，缺省 Y）
- 各步有 hint/说明文字，光标键可选，回车确认
- 完成 outro 列出写入的配置路径；`opencode.json` 生成 `.bak` 备份
- skills 目录出现 `workflow-authoring` / `workflow-optimize`

**I-2 模型输入校验**：模型提问处输入 `abc`
- 即时报错提示「格式应为 providerID/modelId」，不进入下一步；改对了才放行

**I-3 取消路径**：任意提问处 Ctrl-C（或 Esc）
- outro 显示「已取消」，**配置零改动**（对比 .bak / 原文件）

**I-4 重复安装幂等**：紧接着再跑一次 install，全部同答
- 不产生重复插件条目；旧配置仍先备份 .bak

**I-5 skills 覆盖确认**：先删掉 `skills/workflow-authoring` 里任意一个文件再重装 skills
- 弹「skill 目录已存在，覆盖吗」确认；选是 → 目录恢复完整

**I-6 全局 / 锁定模式**（各跑一遍，建议用临时 HOME 与干净目录）
- global：写 `~/.config/opencode/opencode.json`，skills 进全局扫描目录
- locked：执行 npm 安装，配置走包名条目 + 零拷贝 `skills` 数组（指向 `node_modules/…/skills`）

**I-7 doctor**：`npx @mickorz/opencode-agentic-workflow doctor`（装好后）
- 各检查项 `[OK]`；无 FAIL；版本显示与 `npm view … version` 一致

**I-8 update**：`npx @mickorz/opencode-agentic-workflow update`
- 条目 package 解析为 npm 最新版；结束后 doctor 版本对齐

**I-9 交互卸载**：`npx @mickorz/opencode-agentic-workflow uninstall`
- multiselect 勾选要卸载的方式；确认问句列出所选项
- skill 目录删除确认**缺省 No**（用户数据不自动删）
- outro 输出「手动清理清单」（journal 运行记录等用户数据路径）
- 卸载后 `opencode.json` 无残留空键；只剩 $schema 空壳时整文件删（含 .bak 处理）
