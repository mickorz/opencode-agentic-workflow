## P2.2 交付清单（Commit 14）

- `sequence(steps, { journal })`：journal 感知执行——每步 `stepStarted(i, prev)` / `stepCompleted(i, output)` / `stepFailed(i, cause)` 落盘；run 级 `complete()/fail()` 收口（fail-fast 与 continue 模式均覆盖）
- `resumeSequence(store, runId, steps, options)`：
  - run 已 completed → **幂等**直接返回最后一步 journal 输出（不执行任何步骤）
  - 失败/崩溃中断 → `reopen()` 重置未完成步骤，跳过 completed 前缀（prev 链取 journal 输出），从第一个未完成步骤重跑

- `RunJournal.reopen()`：failed/aborted → running，未完成步骤连同 input/output/时间戳/错误重置 pending；completed 步骤原样保留（completed run 拒绝 reopen）
- **明确边界**：仅 sequence 恢复（parallel/nested 不做）；重跑意味着该步骤副作用再次发生（非幂等步骤需自行保证安全）；工具层接线（runId 透传/恢复入口）随 Commit 20 e2e 落地

## P1.3 交付清单（Commit 09）

- `src/runtime/errors.ts`：统一错误家族
  - `WorkflowError` 基类；`WorkflowCheckError` / `WorkflowVerifyError` 归宗
  - `WorkflowStepError`（stepIndex + cause 链）；`WorkflowSequenceError`（errors 累积 + lastValue）；`WorkflowParallelError`（failures + results + mode）
  - P1.4 的 retry/fallback 只捕 `WorkflowError` 家族，业务异常经 cause 链保留
- `sequence(steps, { onFailure, stepNames })`：
  - `fail-fast`（默认）：首败即抛 WorkflowSequenceError，剩余步骤不执行
  - `continue`：失败步骤记录后继续（prev = 最后一次成功值），全部执行完仍抛错（累积全部错误）
- `parallel(tasks, { onFailure })`：
  - `fail-fast`（默认）：首败即抛；晚到失败被吞掉（无 unhandled rejection，已测）
  - `collect`：等全部落定再抛，携带全部失败与成功结果（完整可观测）
  - `partial`：尽力而为，失败槽位 undefined，不抛错
- rejection 契约：sequence/parallel 拒绝时一律抛 Workflow 系错误（P0 裸异常行为升级）
- 测试：单测 42/42（新增 10，含 unhandled rejection 防回归与空数组边界）
